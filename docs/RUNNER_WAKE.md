# Побудка pull-раннеров

`forge_ci provider=github|gitverse|moshub|gigaide mode=runner idempotency_key=…`
будит площадку без публикации исходников. `commit` не нужен. Ожидайте тот же job
через `job_wait`; JSON результата имеет схему `mcpshka.runner-wake/v1`.

Для CI Go-процесс создаёт одноразовую регистрацию на 20 минут и передаёт её
скрипту только через окружение. Скрипт отправляет один POST на `main`.
После неоднозначного ответа `DISPATCH_UNVERIFIED_DO_NOT_REPLAY` сначала проверьте
регистрацию через `runner_status`; не отправляйте новый dispatch вслепую.
`accepted` означает принятую побудку, а результат теста показывает `runner_status`.

GitHub/GitVerse запускают `runner.yml`, MosHub — отдельный job `runner`.
На площадке одновременно работает один такой job, максимум 45 минут;
агент выходит после трёх минут без заданий. Ключ регистрации читается из
окружения, конфигурация лежит во временном каталоге. Токен GitHub/GitVerse
маскируется до запуска агента; токен MosHub не подставляется в команды.

Публичный адрес берётся из того же `MCPSHKA_PASSKEY_ORIGIN`, что и `/runner/setup`.
Ключи API площадок остаются на H96, в существующих хранилищах forge CI.

## GigaIDE

Адрес пространства не найден в текущей записи `provider/gigaide-cloud`.
Оператор задаёт `MCPSHKA_GIGAIDE_WORKSPACE_URL` в окружении MCPshka.
Побудка открывает этот URL существующим браузером с сохранённым профилем
его хоста, затем ждёт IDE. `browser_run site=gigaide` использует тот же профиль.
При странице входа возвращается `LOGIN_NEEDED`; повторный вход выполняет владелец.

Установщик `/runner/setup` сохраняет агент и ключ в пространстве,
добавляет запуск в `.bashrc` и создаёт `keeper.code-workspace`.
Откройте этот workspace и один раз разрешите автоматические задачи:
его задача `folderOpen` запускает агент и при отсутствии восстановленного терминала.
Открытый каталог MCPshka также содержит такую задачу.
Побудка подтверждает открытие IDE; регистрацию агента проверяйте отдельно.

Контракты: [GitHub dispatch](https://docs.github.com/en/rest/actions/workflows),
[GitLab pipeline](https://docs.gitlab.com/api/pipelines/),
[VS Code automatic tasks](https://code.visualstudio.com/docs/debugtest/tasks).

## Авторежим 0.16.5

Offbox выбирает живой раннер; если подходящего нет, будит площадки по живости
и давности использования. GitVerse с waiting/cancelled и MosHub без online
appsechub-раннера не получают новые задания. При недоступности CI очередь
доходит до GigaIDE. `postStartCommand` запускает `.devcontainer/start-runner.sh`;
блокировка агента не даёт повторному пробуждению создать второй процесс.

Для автоматической GigaIDE-побудки нужен наблюдённый остаток бесплатного бюджета
`MCPSHKA_GIGAIDE_VCPU_HOURS_REMAINING`. Резервируется время ограниченной сессии
(два vCPU, минимум час); неизвестный или недостаточный остаток запрещает
побудку. Резерв и одна незавершённая побудка сохраняются между процессами.
Регистрацию, online/offline и последнюю задачу показывают runner_status и MOTD.

и мгновенные cancelled; подтверждения исчерпания квоты нет. MosHub API
доступен, последний наблюдаемый pipeline 95602 от 12.11 завершился failed;
одного этого статуса недостаточно для вывода о причине или квоте.
