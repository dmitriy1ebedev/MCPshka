# MCPshka 0.1.170 — тест модуля без ручного fence, надёжная публикация main

Первый выпуск по локальному конвейеру без GitHub (после установки 0.1.169).

## Исправлено
- **Sealed-тест завершается сам** (BUG-20261022-52): как только результат записан, фоновый обход брокера выполняет штатный fence точного permit/launch (идемпотентно, потерянный ответ восстанавливается наблюдением). Раньше без ручного `executor-canary canary-fence` юнит висел до часового лимита. `executor-canary status` и `integration_test_prepare` отдают `next_action`.
- **Открытие базы состояния под нагрузкой** (BUG-20261022-53): проверка и миграция схемы в `statestore.Open` получают общий бюджет 30 с; обычные операции остаются на 5 с. Тест модуля падал на открытии SQLite в нагруженной песочнице.
- **`integration_publish_main` не оставляет checkout наполовину обновлённым** (BUG-20261022-54): до перемотки проверяется, что каждый изменяемый каталог доступен на запись; иначе HOLD с перечнем путей и без изменений. 0.1.169 публиковался с root-владельцами в `internal/releaseprep` и оборвался посередине.
