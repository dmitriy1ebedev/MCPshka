# MCPshka 0.12.5 — тихий хост

## Зачем

09.11 H96 завис на 3,5 часа в свопе (MCP-159). Каждый запуск процесса на хосте, которому не хватает памяти, — это major faults и подкачка бинарника с eMMC. Замер 13.11 (tracefs, 60 с, покой): брокер запускал 108 `sqlite3` (исправлено в 0.12.4) и 15 `systemctl`, сервер — `systemctl` и `git`, homeguard — `docker` с его помощниками.

## systemd по D-Bus (`internal/unitbus`)

Небольшой клиент D-Bus на стандартной библиотеке: root (брокер) говорит с systemd напрямую через `/run/systemd/private`, служебный пользователь — через системную шину. Соединение одно и держится открытым; любая ошибка его закрывает, и этот запрос выполняет `systemctl`, как раньше.

Пакет отвечает только на `systemctl show … --property=…` и пишет вывод так же, как systemctl 257: строки, да/нет, числа, `…Monotonic`, интервалы `…USec` (`1min 30s`, `infinity`), `InvocationID`, списки юнитов. Маски (`mcpshka-executor-*.service`) раскрываются как у systemctl: без `--all` — только активные юниты или с заданием, в порядке systemd. Метки времени, права, массивы структур и неизвестные свойства не угадываются — такой запрос целиком идёт в systemctl. Тест `TestShowMatchesSystemctl` сверяет вывод побайтно с настоящим systemctl на хосте.

Переведены: здоровье юнитов исполнителя и `systemctl` брокера (через него ходят `service_status`/`service_list`), доказательства fence исполнителя, проверка scope заданий, снимок control path, опросы `release_apply_status`, `diag_release_status`, `project_release`, миссий, агентов и MainPID MCPshka. Выключатель — `MCPSHKA_UNITBUS=0`.

## Docker без CLI

Список контейнеров, который сервер спрашивает у брокера каждые несколько секунд (host_triage, здоровье, самолечение — 23 запуска `docker ps` в минуту по замеру 13.11), брокер берёт из сокета Engine API: те же строки JSON с полями, которые читают все потребители (Names, Image, State, Status — Status в формулировке самого Docker), в том же порядке и через тот же фильтр разрешённых контейнеров. Раз в минуту homeguard проверяет Zigbee2MQTT и MQTT (`inspect` и журнал за 2 минуты) — тоже через сокет. Недоступный сокет — по-прежнему CLI. Клиент один на оба места — `internal/dockerapi`; проверка доказательств исполнителя и здоровье брокера читают systemd через общий `unitbus.Bounded` (тот же бюджет 8/16 КиБ).

## Бюджет памяти в host_triage

Новое предупреждение `memory_budget`: сумма анонимной и выгруженной памяти по cgroup v2 больше RAM — хост перегружен ещё до трэша. Кэш страниц не считается (он освобождается), zswap не мешает (считается логический объём). В тексте — пять самых тяжёлых юнитов, контейнеры по короткому id.

## Старые напоминания автовыпуска

Остановленный автовыпуск оставляет напоминание, и его видно в MOTD и в SessionStart. Раньше оно висело, пока его не закроют руками: «Автовыпуск 0.11.10» провисел сутки после того, как 0.12.4 уже стоял. Теперь выпуск, дошедший до DONE, закрывает все открытые напоминания `release_queue/*` (`memory.Store.CloseReminders`).
