# MCPshka 0.12.1

Исправления, найденные живой приёмкой 0.12.0 в проде.

## Облака: зависшая операция больше не запирает хранилище

9 ноября создание папки на Google Drive упёрлось в лимит общего ключа rclone и осталось в состоянии UNKNOWN. С тех пор любая загрузка, перенос и создание папки в любом облаке отвечали «storage worker busy or UNKNOWN» — снять это можно было только правкой журнала руками.

Теперь исход такой операции выясняется чтением облака:

- папка или файл на месте (для загрузки — того же размера) — операция закрывается как выполненная;
- следов нет — как несостоявшаяся, её можно повторить с новым ключом;
- облако прочитать не удалось — остаётся UNKNOWN, следующая попытка проверит снова.

Сверка идёт сама: при `storage_transfer_status` и при приёме следующей операции. Пока рабочий процесс операции жив, она по-прежнему считается занятой. Резервные копии (`backup_create`, `backup_verify`) продолжают восстанавливаться по своим контрольным точкам.

Сообщение о занятости называет операцию и что с ней делать, а не «reconcile its status first».

## Документы: работа до результата

- `doc_edit` понимает очевидные варианты записи: `heading {text, level}`, `paragraph`, `table` и `values` вместо `rows`, `range` вместо `start`.
- На неизвестную операцию ответ перечисляет встроенные операции для этого вида документа и напоминает про `script`.

## Автовыпуск убирает за собой (MCP-170)

После DONE очередь выпуска снимает рабочее дерево влитой ветки — только если оно чистое и его lease никто не держит (ветка остаётся) — и упаковывает git (`gc --auto` с порогом 1500 объектов). Что сделано, видно строками CLEANUP в истории выпуска; сбой уборки на итог выпуска не влияет.

## approved_task: «exit status 1» без текста (MCP-177)

Поиск по журналу (`journalctl -g`, `grep`) при отсутствии совпадений завершается кодом 1 и ничего не печатает — задача выглядела как необъяснимый отказ. Теперь ошибка говорит: команда отработала и ничего не вывела, для поиска это NO_MATCHES. Журналы служб Lane с 0.12.0 читаются и без Face ID — `journal_read`.
