# MCPshka 0.16.1 — распределённый CI

Выпуск 2026-11-18. Идея владельца: проверка выпуска не зависит от одной площадки и не грузит H96.

- `forge_ci provider=distributed mode=plan|publish|status commit=<sha>`: три LPT-шарда по закреплённой в `packaging/ci/plan.json` истории времени; для неизвестного пакета — число Test-функций. Инвентарь — `go list ./...` по файлам точного коммита. Состав и hash плана стабильны для коммита; UTC-день вращает только назначение площадок.
- Перед назначением проверяются API/авторизация, Actions permissions и бесплатная квота GitHub, доступность CI GitVerse и online runner MosHub с tag appsechub. Неизвестная квота не разрешает платное использование.
- Все площадки получают один и тот же parentless snapshot с Source-Commit/Source-Tree, совпадающий с алгоритмом GitVerse. Отдельный ref `mcpshka-distributed/<sha>` и dispatch-only workflow предотвращают параллельный запуск прежнего полного gate. SourceCraft остаётся зеркалом.
- Каждый job выполняет только `go vet` и `go test -json -count=1 -p 1` своего списка пакетов. Ошибка кода — FAILED с пакетами и площадкой. Подтверждённый инфраструктурный отказ переносит только шард; неизвестный результат/подмена доказательства — HOLD. Dispatch резервируется до POST, потерянный ответ сверяется без повторной отправки. Неназначенный job ограничен ожиданием, а не вечным waiting.
- `integration_ship evidence=distributed`: root сам перечитывает CI API, сверяет ожидаемый snapshot SHA/source_tree, hash плана, конкретный shard/run и полное покрытие пакетов. Наблюдения остаются UNTRUSTED; запечатывание и fencing используют существующий конвейер.
- Последний резерв — H96: отдельный запечатанный module-worker только недостающего шарда, через общую тяжёлую очередь, по одному. Частичный permit никогда не принимается как полный module-gate. Broker не держит длинный синхронный запрос. Совместимость evidence ci/gitverse/module сохраняется.
- `mode=status` возвращает таблицу shard → provider → state → seconds, в том числе наблюдения H96 через существующий broker status; `tool_usage.ci_providers` показывает длительности площадок последнего наблюдаемого распределённого прогона.
- В cloud dependencies добавлен PyYAML; MosHub получил отдельные jobs по shard, необходимые зависимости и сохранённый режим offline-образа.

## Проверка и внешние условия

Проверки — через очередь MCPshka, целевыми пакетами, без полного `./...` на H96. Фикстуры покрывают недоступность, infra/code failure, подмену snapshot/tree, неполное/дублированное покрытие, изоляцию частичного module-permit, квоту и workflow-контракты.

Актуальный аудит — [FORGES.md](../ci/FORGES.md). GitHub billing API возвращает 403 (нужен Plan: read на аккаунт) — тогда расход считается по billable timing прогонов своего репо за месяц ×1.25 + 300 минут запаса на прочие репо, GitHub не выпадает. Последний MosHub job не получил appsechub runner; нужен online runner и актуальный offline-образ MOSHUB_CI_IMAGE. Эти условия не блокируют остальные площадки и резерв отдельных шардов.

Ревью Claude Code: проверка доказательств (commit/tree/snapshot/plan hash/покрытие) принята; квота GitHub — собственный подсчёт. Живой распределённый прогон — первым же коммитом после установки 0.16.1 (сам 0.16.1 вливается evidence=module: в 0.16.0 распределённого режима ещё нет).
