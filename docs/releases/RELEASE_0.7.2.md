# MCPshka 0.7.2 — 2026-11-04

Закрывает класс ошибок «before probe failed» у мутирующих инструментов целиком, а не по одному.

## Исправлено

- **MCP-132 (P1, нашёл DIAG).** `phase_checkpoint_record` останавливался на «before probe failed; request held: path is empty»: проба контракта `phase_gate` вызывалась без аргументов. Та же причина, что у MCP-130. Ручной разбор аргументов в `toolcontract.ProbeArguments` есть не для всех проб: из ~300 инструментов у трёх десятков проб его не было.
  - `fillProbeArgs`: обязательные и необязательные поля пробы, которых нет в явном разборе, берутся из входа мутации под тем же именем. Ключ повтора не копируется, явный разбор имеет приоритет.
  - `allProbeGaps` при старте (`validate`) проверяет каждый мутирующий инструмент каталога. Если обязательное поле пробы не может прийти ни из явного разбора, ни из входа мутации, сервер падает при запуске, а с ним тесты и CI. Новый контракт с несовместимой пробой не соберётся в выпуск.
  - Сбой before-пробы на свежем ключе снимает его (`Discard`): ничего не выполнялось, тот же вызов можно повторить. Повтор уже зависшего ключа удержание не снимает.
- Гайд: в цикле фазы и шаблоне задания агенту появился шаг `phase_checkpoint_record` перед `phase_gate`.

## Для DIAG

Ключ `diag-p39-checkpoint-honest-evidence-20261104-v1` эффекта не имел: `phase_gate P39` показывает checkpoint MISSING. После 0.7.2 чекпоинт P39 нужно записать с новым ключом.
