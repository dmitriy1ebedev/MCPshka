# MCPshka 0.9.3 — смена «мозгов» и чистый конвейер

Дата подготовки: 2026-11-08.
Статус: CANDIDATE до `project_verify expected_version=0.9.3`.
База: main 4ef228b (0.9.2, откат — 0.9.2).

## Включено

- **«Мозги» в веб-настройках** — на странице «Подключения» группа «Мозги: ИИ-чаты
  с доступом к MCPshka». Claude и ChatGPT (`chatgpt.com/connector_platform_oauth_redirect`)
  встроены и включены; кнопка «Выключить» отрезает ИИ сразу — регистрацию,
  вход, обновление токена и каждый вызов. Неизвестный ИИ (Kimi и др.) после
  первой попытки подключения появляется строкой «ждёт разрешения» с кнопкой
  «Разрешить». Только https, не больше 8 запомненных адресов. Каждый вход —
  по-прежнему с Face ID.
- **MCP-149** — вливание само переключает чистую рабочую копию на main;
  detached HEAD, правки в отслеживаемых файлах и отказ switch — типизированный HOLD
  без эффекта. Ручной `git switch main` после каждого выпуска больше не нужен
  (действует со следующего выпуска: публикует уже установленная версия).
- **MCP-150** — один маршрут тестов: `exec_start` отказывает в `go test`,
  `pytest`, `npm test` с `TEST_ROUTE_PROJECT_TEST` и ведёт в `project_test`
  (`packages`/`run` — подмножество).
- **Аудит инструментов (MCP-151, часть)** — `host_triage` предлагал шаги с
  неверными полями (`{"name":…}`), и такой вызов всегда падал; теперь там
  `docker_action`/`docker_logs`/`service_action`/`journal_read` с полями схемы.
  Дубли `docker_restart`, `service_restart`, `service_logs` помечены «Устарело»
  и не выдаются поиском (`tool_resolve`), если их не назвать точно.
  Постоянный линт `TestToolCatalogLint` проверяет каждый следующий шаг:
  инструмент существует, поля есть в схеме, нет ссылок на дубли, у
  изменяющих инструментов есть probe/recovery-контракт, каталог не растёт
  сверх бюджета (281) без причины. Правило 5: steps миссии — id этапов ROADMAP.
  Русские запросы «перезапусти контейнер», «логи службы» ведут прямо в
  `docker_action`/`service_action`/`journal_read`.
- **Подготовка запечатанного прогона по гибкому бюджету** — была жёстко 90 с и
  на нагруженной H96 (load 5) истекала до старта тестов с безликим
  «admission or fencing unverified». Теперь `budget.Phase`: 2 мин, под
  нагрузкой до 4 мин; срок юнита и окно наблюдения выведены из того же
  максимума; истёкший бюджет в журнале — `CONTEXT_DEADLINE`.
