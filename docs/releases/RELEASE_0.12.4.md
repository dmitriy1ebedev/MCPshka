# MCPshka 0.12.4

## Яндекс.Диск: без «быстрого способа»

После входа через приложение rclone Яндекс выдавал токен, но API отвечал `410 GoneError` («Ресурс больше недоступен») на любой список файлов. Так с 11.10.2026 у всех, кто ходит в Диск приложением rclone (rclone issue #10067); информация о Диске при этом читается.

Мастер подключения Яндекса теперь предлагает только своё приложение (oauth.yandex.ru, один раз) и объясняет почему. На странице «Подключения» кнопка «Подключить» для Яндекса и Google ведёт в тот же мастер; вход через rclone с вставкой адреса 127.0.0.1 остался для Dropbox и OneDrive. Запасной путь без OAuth-приложения — «Яндекс Диск по паролю приложения» (WebDAV).

## Брокер: меньше процессов в покое (MCP-164)

Замер 13.11 (60 с, tracefs): брокер запускал 108 процессов `sqlite3` в минуту. Каждое открытие базы исполнителя (`/var/lib/mcpshka-executor/state.db`, на каждый запрос исполнителя) проверяло версию схемы, WAL и таблицы четырьмя отдельными sqlite3. Проверки уже инициализированной базы идут по постоянному соединению; холодное, занятое или сбойное соединение уступает прежнему разовому пути, создание новой базы — всегда разовым путём.
