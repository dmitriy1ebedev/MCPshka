# MCPshka 0.2.2

Исправления, найденные при выпуске и приёмке 0.2.1 (Tier 1).

- Выпуск: проверка доказательства и воркер вливания больше не требуют, чтобы `integration_ship` застал их живыми — результат, записанный до остановки юнита systemd, принимается по доказанной остановке (BUG-126/95); ответ ship укладывается в ~15 с, длинные шаги идут в фоне (BUG-104/108); `forge_ci publish` повторяет временные сетевые сбои GitVerse (BUG-125).
- `rescue_start rollback` откатывает пару controller+broker через журнал coordinated-upgrade и находит кандидатов с хешем в имени (BUG-127).
- Health: свежесть и проверка восстановления ежедневного шифрованного бэкапа состояния видны в `storage_backup` (BUG-128).
- `tool_forge audit`: шаблонные описания storage_* больше не дают ложных overlap (BUG-116).
- Face ID для программ и устройств: `approved_task_execute` (сборка IPK, установка на LG и др.) больше не требует после Face ID ещё и `mcpshka approval-grant` в root-терминале — достаточно собственного Face ID-гранта задания.
- `ha_exposure_sync entities=[...]`: добавляет в Алису/HomeKit ровно выбранные сущности (без лишних USB и недоступных), а в плане видно «потерянные» сущности экспорта, которых больше нет в HA.
- Самодостройка: `tool_forge action=build` — недостающий инструмент дописывает сам чат через MCP (ветка forge/<id>, lease, цикл в `mcpshka_guide topic=forge`); агенту — только если владелец назвал исполнителя.
- Тесты executor под root: фикстуры защищённого ядра явно пропускаются с причиной (BUG-20261020-10).
