# MCPshka 0.11.3 «Память, которая находит»

Задача владельца (10.11): «как получать максимум результативную память, чтобы прям хорошо было»; «MCPshka должна чекать, что я к её памяти взываю или говорю „поищи в базе знаний“»; объём — пункты 1–4, MCP-168, MCP-169 и пункты роадмапа, без сокращения; баг, пойманный тестом, чинится в этой же итерации.

1. **Экзамен памяти.** 65 вопросов словами владельца (по одному на каждое важное правило и решение, с перефразировками) зашиты в бинарник (`internal/memory/exam.json`). `mcpshka memory-eval` печатает R@1/R@3 и промахи, код выхода 1 ниже цели; `phase_gate` для дерева MCPshka добавляет проверку `memory_exam` по живой памяти (цель R@1 ≥ 0,85, R@3 ≥ 0,95). Вопросы записей экзамен не копируют (проверено скриптом).
2. **Запись знает свои вопросы (doc2query).** `memory_write record.questions` — 5–10 способов, которыми владелец о ней спросит; `memory_write question_sets` добавляет вопросы уже существующим записям (своим — по source, копиям знаний — по id), `memory_recall without_questions` показывает, кому их не хватает; `mcpshka memory-questions FILE.json` — пачкой. Вопросы лежат в `mem_q` по ключу записи, поэтому переживают новую версию записи, повторный импорт и пересборку копии знаний, и индексируются вместе с записью.
3. **Меньше шума.** В журналах (checkpoint/log) текущим остаётся только последний раздел, старые — вид `archive` с весом 0,6; повторный импорт закрывает разделы файла, которых больше нет в источнике (раньше пере-нарезка оставляла старые «части» отвечать).
4. **Поиск по смыслу.** Векторы слов Natasha navec (hudlit, 12 млрд слов русской прозы, MIT) обучены вне H96; `mcpshka memory-vectors` один раз скачивает закреплённый пакет (SHA-256 проверяется), оставляет 120 тыс. частых слов в одном файле (~12 МБ) и пересчитывает векторы записей. На H96 — только поиск слова в таблице и среднее (SIF), без модели и сети при чтении. `memory_recall` сливает слова (BM25), формы (триграммы) и смысл (косинус ≥ 0,45) через RRF, в `why` — «смысл #N».
   Настройка по экзамену (копия живой памяти): BM25 с весами колонок заголовок 3 / тело 0,5 / вопросы 2, RRF k=4, формы ×0,7, смысл ×0,6 при косинусе ≥ 0,35; стоп-слова («что», «как», «надо», «делать»…) не участвуют в словесном поиске; словарь владельца добавляет к запросу написание записей («мспишка» → MCPshka, «лиз» → lease, «гит» → git, «фейс айди» → Face ID, «впс» → VPS, «мсп» → MCP, «лейн» → Lane…). Итог на 65 вопросах: R@1 0,62 → **0,877**, R@3 0,86 → **0,985** (только векторы без вопросов давали 0,585 — смысл помогает лишь вместе с весами и словарём).
5. **MCPshka слышит «вспомни».** Первая строка инструкций сервера и `topic=rules`: на «вспомни», «поищи в базе (знаний)», «мы уже находили/решали», «как в прошлый раз» — до ответа `memory_recall` с этими словами. Описание и русские синонимы `memory_recall` содержат те же фразы. Для Claude Code — хук `UserPromptSubmit` (`packaging/claude/`, ставится `install-memory-hook.sh`): он сам кладёт найденное в контекст (`mcpshka memory-recall`).
6. **MCP-168.** `memory-import` из недоступного или пустого каталога — ошибка с кодом ≠ 0, а не «files: 0».
7. **MCP-169.** `mission_status` оценивает до 256 наблюдений и показывает 16 самых срочных (blocked/unknown первыми), остальные — счётчик `omitted`; переполнение списка больше не делает отчёт `unknown`.
8. **Импорт архивов чатов выжимкой.** Выгрузка ChatGPT/Claude (`conversations.json` или zip) в `memory-inbox` (страница «Память» или копия) режется на куски по беседам (`mcpshka memory-inbox`, ночной цикл, загрузка со страницы). ИИ берёт следующие куски `memory_recall inbox=true` и выжимает 0–5 записей `memory_write` (source = id куска) или пропускает `inbox_skip`; покрытие — в `memory-brief`/MOTD («ждут N, готово M»). Разбор выгрузок общий с `knowledge_import_chat` (`knowledge.ParseChat`).
9. **MCP-163.** Дубли `docker_restart`, `service_restart`, `service_logs` (0 вызовов с 08.11) удалены совсем: перезапуск — `docker_action`/`service_action action=restart` (тот же список разрешённых), журнал — `journal_read`; боевой smoke переведён на `journal_read`. Из `tools/list` убраны 37 не вызывавшихся с 08.11 семейства `codex_*`, `cloud_*`, `project_lease_admin_fence_*/recover*`, `executor_fence*`, `executor_admin_stale_*`, `workflow_checkpoint_*`. Они зарегистрированы, вызываются по имени и через `tool_invoke`, их предлагает `tool_resolve`, `tool_usage` их считает; клиент без них не считается устаревшим. Бюджет каталога 288 → 250: зарегистрировано 285, в `tools/list` 248.
10. **Единые ROADMAP и орфография.** Пакет `roadmapstyle`: один шаблон (разделы «Релизы», «Очередь», «Реестр багов»; версии просто 0.N.M; статусы «в проде / заменён / план / в сборке / откат / отозван»), словарь терминов (MCPshka, Lane, DIAG, Face ID, GitVerse, Codex, ChatGPT, GitHub; цитаты в «», код и ссылки не трогаются). `project_context.roadmap_style` и `phase_gate roadmap_style` (WARN) показывают отклонения живого ROADMAP; CI проверяет орфографию отслеживаемых документов. Методология — guide `topic=roadmap` (раздел «Единый шаблон ROADMAP»).

11. **Автовыпуск 0.11.2 вставал на SHIP.** `release_apply action=queue` писал «unknown tool "integration_ship"»: инструмент был зарегистрирован в обход `addTool`, без вызова по имени, поэтому ни сторож, ни `tool_invoke` не могли его вызвать. Пойман на выпуске этой версии; теперь вызывается по имени (тест `TestIntegrationShipCallableByName`). 0.11.3 выпущена вручную по регламенту.
