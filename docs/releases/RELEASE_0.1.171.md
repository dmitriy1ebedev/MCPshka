# MCPshka 0.1.171 — меньше шагов, честные внешние CI, рабочий локальный выпуск

Включает 0.1.170 (авто-fence изолированных тестов, бюджет открытия SQLite, безопасная публикация main).

## Меньше шагов на задачу (по мировой практике MCP)
- **`integration_ship`** — вливание одним инструментом по шагам: каждый вызов делает следующий безопасный шаг (очередь → изолированный тест → запуск → fence → … → воркер → сверка → публикация main) через те же обёрнутые инструменты, ключи повтора выводятся из коммита и шага, в ответе — этап, все ID и `next_action`. Ревью остаётся явным: на `READY_FOR_APPROVAL` нужен отдельный `integration_approve`, его `approval_id` передаётся обратно. Было 9 ручных вызовов в строгом порядке.
- **`tool_resolve compact=true`** — только имя, эффект, схема входа и контракт мутации, без схем выхода: по всему каталогу ответ минимум вдвое меньше (для ChatGPT, который держит часть каталога).
- **Причины HOLD различимы** (BUG-20261022-55, Codex): диск («нужно N свободно, есть M»), повторный fence, незарегистрированный запуск и др. вместо одного «admission or fencing unverified»; `errors.Is(err, ErrHold)` сохранён.

## Локальный выпуск без GitHub — исправлен
- **`release_local`**: брокер принимает только PID контроллера, а `release_prepare source=local` ходил в него из отдельного задания — первый настоящий локальный выпуск получил «connection reset by peer». Теперь каждый вызов делает один шаг внутри процесса MCPshka: запуск запечатанной сборки, ожидание, fence, квитанция, оба образа, идемпотентная раскладка в `bin/`.

## Внешние CI
- **`forge_ci status`** работает на живых площадках: GitVerse ставит прогоны в `waiting`/`running` (раньше «unknown_run_state»), скрипт MosHub падал на импорте под `python3 -I`.
- **GitVerse `release-suite` впервые зелёный**: тесты от непривилегированного пользователя (раннер — root), Git 2.44+ (MCPshka использует `--no-lazy-fetch`), `tini` как subreaper.
- **MosHub**: у раннера нет выхода в интернет (ни deb.debian.org, ни зеркала) — образ CI со всеми зависимостями в реестре проекта (`packaging/moshub/ci-image`).

## Исправлено
- Уборка кандидатов сверяет содержимое, а не только метки времени: на файловых системах с грубыми метками подмена того же размера проходила (найдено на раннере GitVerse).
