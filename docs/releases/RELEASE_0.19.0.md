# MCPshka 0.19.0

Ночной крупный выпуск 24–25.11: монолиты режутся дальше, MCPshka впитывает лучшее из Remote Desktop Commander и Claude Code, у неё появился свой «мозг» на GigaChat/FreeLLM, закрыты карточки по CI, lease, Face ID и H96.

## Монолиты и open-core
- Из mcpserver вынесены phase gate (`internal/phasegate`), project_context (`internal/projectctx`), классификация сбоев (`internal/failure`), approved_task (`internal/tools/approvedtask`). Из rootbroker — docker terminal, self-test, Docker smoke, agentlogin, wifiscan, rootledgerreap, diagobserver, diagcontract, hostcleanup, установка DIAG (`internal/diagrelease`). Из executor — `internal/unitfence`, `internal/sandboxbind`. Проверка `systemd-run` — `internal/transientunit`. Потолки archlint: mcpserver 8795, rootbroker 9553, executor 9806.
- **Храповик archlint:** пакет, ставший меньше своего потолка больше чем на 40 строк, роняет тест: потолок опускается в том же коммите. Число инструментов внутри mcpserver не растёт (111): новый инструмент идёт в `internal/tools/<имя>` (S5.LEAN).
- **Граница open-core:** archlint не даёт ядру новых импортов домашних дополнений (Lane, HA, Venta, webOS, go2rtc, Wi-Fi, DIAG); `opencore` — аудит дерева перед публикацией (почты, tailnet, частные IP, домашние пути, секреты — маскированы).

## Из Remote Desktop Commander
- **fs_patch при промахе** называет ближайший фрагмент: строку, сколько строк совпало, только ли пробелы, первую различающуюся строку, CRLF/LF; при неоднозначности — строки всех совпадений.
- **job_output cursor<0** читает хвост вывода (как offset -N).
- **fs_find context_lines 0..5** — строки до и после совпадения.
- **fs_read:** окно по байтам больше не режет кириллическую букву (раньше весь кусок уходил в base64); `line=N` открывает файл с номера строки из fs_find.
- **fs_write append=true:** большой файл пишется кусками по 64 КБ под тем же SHA-замком (до 4 МБ).
- **job_wait** просыпается по смене фазы задания, а не опросом раз в 500 мс (MCP-273).

## Из Claude Code (/tasks, /status)
- **mission_status — единый список «что запущено»:** к agent_task, roadmap_run, интеграциям и lease добавлены задания очереди (тесты, сборки, exec); у каждого пункта `stop` — точный вызов остановки. Новых инструментов нет.
- **host_triage — доктор конфигов:** битый `/etc/mcpshka/*.json|*.env` — critical с файлом и строкой (значения не показываются) и ближайшим .bak для сравнения. Плюс refs в `/root/repos/*/.git`, принадлежащие чужому пользователю (MCP-254), с точным chown.

## Мозг MCPshka
- **Ночной FreeLLM-конвейер:** правка модели с верными строками, но неверными отступами (пробелы вместо табов, срезанный отступ) больше не отбрасывается. Совпадающее ровно один раз место берётся из файла, у new отступ переносится (MCP-239).
- **brain_ask / brain_status / brain_cancel:** любой ИИ с вызовом функций (GigaChat, FreeLLM, OpenAI-совместимый) работает через MCPshka в фоне; все вызовы идут путём tool_invoke — политика, Face ID и lease те же; инструменты владельца и запуск агентов запрещены.
- **llmgateway:** запасные endpoint'ы, OAuth-обмен ключа со своим CA (GigaChat), function calling, лимит параллельных запросов на endpoint; embedding-модели не считаются чат-моделями.

## CI и выпуск
- **CI_STUCK заработал:** стоп после трёх отмен GitVerse в 0.18.0 не мог сработать (ci_status отдаёт один прогон). Теперь ci_status даёт `recent_outcomes`, а forge_ci publish того же коммита после трёх одинаковых сбоев отвечает CI_REPEATED_FAILURE (S5.DIAGCI).
- **Контрольный образец CI:** если прогон не стартует, forge_ci status смотрит, когда реально работали прогоны других репозиториев аккаунта, и отличает блок одного репозитория (CI_REPO_BLOCKED) от остановки площадки или аккаунта (CI_ACCOUNT_STALLED: не перепубликовать, брать evidence=module). Живой замер 25.11: на GitVerse ничего не работало с 16.11 (S5.DIAGCI).
- **Один локальный прогон на коммит:** если ни один внешний раннер не взял тест, H96 запускает коммит один раз; повтор ссылается на это задание (S5.DIAGCI).
- Недоступная CI-площадка называет причину; VERIFY принимает запечатанный модульный тест; MosHub не публикуется, пока все конвейеры висят.
- **Lane-рецепт выпуска** проверен на живых формах вывода Lane (MCP-171); профильный Go-тест проекта снова запечатан (MCP-270).
- Отказ по схеме инструмента подсказывает поля, ближайшее имя и пример.

## H96 и надёжность
- **project_commit отказывает (HOLD), если файл после твоего fs_write/fs_patch под lease изменил кто-то другой** (MCP-217).
- **Face ID на iPhone:** если прошлое подтверждение не дошло, а сервер всё ещё ждёт — кнопка снова доступна для нового запроса; старая подпись не переотправляется (MCP-243).
- **P5.3:** project_verify проверяет, что тяжёлые задания действительно вне cgroup сервера (`heavy_jobs_isolated`); откат выпуска больше не выключает приоритет дома навсегда; ручные drop-in'ы с теми же весами принимаются.
- **unitbus:** соединение брокера с приватным сокетом systemd больше не держится открытым между вызовами. systemd шлёт туда все сигналы без подписки; за минуту набегало 315 КБ непрочитанного, вызовы падали с «no reply» и уходили в systemctl. Это и была причина BROKER_CIRCUIT_OPEN: 619 из 639 таймаутов брокера за сутки — systemctl по ~3 с (MCP-256, MCP-273).
- **selfprof:** SIGUSR1 — 30 с CPU-профиль, heap и горутины контроллера и брокера (MCP-273), без порта и перезапуска.
- Телеметрия Go выключена в HOME заданий; GC артефактов собирает scratch заданий удалённых worktree; staging выпуска чистит старые образы; часовая уборка не стопорится на манифесте старого контракта.
- managed-lease внешнего (workbench) владельца снимается после DONE (MCP-265); git_log без шелла (MCP-261/266/268); approved_task под одной Face ID-сессией для планов вне пути управления (MCP-246).
