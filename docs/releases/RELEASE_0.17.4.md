# MCPshka 0.17.4

Сводный выпуск: всё из неустановленной 0.17.3 (MCP-256/257/258/259/262, MCP-271) плюс наработки 20–23.11, которые ещё не были влиты.

- Установка больше не откатывается на послеустановочной проверке. Верификатор запускался через `runuser` с `MCPSHKA_PRIVILEGED_BROKER=1`, а брокер пускает только MainPID `mcpshka.service` и сбрасывал соединение. Из-за этого `installed_version` и `rollback_binary` падали всегда, и установка 0.17.3 откатилась 23.11 15:21. Теперь верификатор работает без брокера, от служебного пользователя, а при отказе в журнал и статус попадают названия упавших проверок, а не голый «exit 1». MCP-275.
- Сборка мусора артефактов заданий (72 ч для успешных, 96 ч для неуспешных — решение владельца 23.11): предпросмотр, применение по Face ID, удаления только внутри своих корней (`os.Root`). MCP-274 (MCP-170).
- `job_wait` опрашивает реже и дешевле. MCP-273.
- projectci не считает пропущенные последующие workflow GitVerse провалом. MCP-272.
- Проверка происхождения CI для чужих проектов (Venta, GitHub Actions) привязана к точному дереву исходников; самопроверка MCPshka остаётся на аутентифицированном корне. MCP-269.
- Типизированный публичный форк на GitHub под Face ID с проверкой родителя. MCP-264.
- Чтение BE900 идёт через нативный читатель MCPshka с длинным таймаутом. MCP-240.
- Метаданные config-entry HA только для чтения и предпроверка смены ключа интеграции без изменений. MCP-241.
- Схема вывода `project_pipeline` проверяется на полных квитанциях. MCP-204.
