# MCPshka 0.11.6 — «Пункты закрываются»

Задача владельца 12.11.2026: «я писал "делай пункты roadmap Lane", он писал коммиты пачками, а по факту ни одного пункта не закрыл». Разбор Lane G0 за 11.11: 60 коммитов с именами GO0…GO5, в ROADMAP закрыто 0 из 6. Причина в MCPshka: сервер не говорил ИИ, что такое «пункт сделан», не выдавал критерий Exit и не умел закрыть пункт; `roadmap_next` и `project_context` называли разный следующий пункт (L2 против G0).

## Что изменилось

| Что | Как |
|---|---|
| `roadmap_next` — наряд на один чекбокс | Пункт берётся из той же фазы, что называет `project_context`. В ответе: `item.id`, текст, `item.exit`, `phase_rules` (обязательные тесты и правила фазы), `also_open`, шесть этапов до закрытия, правило отчёта. |
| `roadmap_close` — новый инструмент | Отмечает пункты `[x]` с датой и заметкой и коммитит ROADMAP под lease — только когда `phase_gate phase=<ID>` даёт PASS по каждому. Отказ ничего не меняет и называет недостающий шаг. До 20 пунктов одним коммитом. |
| Предупреждения | У пункта нет Exit — сначала дописать. После последнего изменения ROADMAP накопилось 10+ коммитов — «ни один пункт ими не закрыт». |
| Правила для ИИ | Первая строка, которую читает любой клиент, `topic=rules` (п. 17) и `topic=roadmap`: пункт = чекбокс, установка и живая проверка — этапы пункта, отчёт — в закрытых пунктах. |
| Уборка | Из `phase_checkpoint_record` убрана повторная проверка входа; логика пунктов живёт в новом пакете `internal/roadmapitem`, пакет `mcpserver` не вырос. |

## Проверка после установки

1. `roadmap_next path=/root/repos/lane` → фаза G0, пункт GO0, Exit про `lane version`, предупреждение о коммитах.
2. `roadmap_close` с непринятым пунктом → отказ `ROADMAP_ITEM_NOT_ACCEPTED`, ROADMAP не изменён.
3. `mcpshka_guide topic=rules` содержит п. 17.

## Не вошло

Сквозной выпуск Lane через MCPshka (MCP-171): этап install для Lane пока идёт через `approved_task_prepare` с Face ID.
