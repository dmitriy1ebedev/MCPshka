# MCPshka 0.13.3 — 2026-11-15

## Добавлено
- P29.N1/N3: ночной разбор карточек проблем. Раз за ночь (02:00–06:00, на тихом хосте) сервер без агентов сверяет каждую активную карточку с живым хостом: держится ли симптом сторожа или исчез, вышло ли исправление в прод и ждёт приёмки, закончил ли агент, давно ли нет движения. В карточку пишется строка только при смене вердикта, отчёт — `issues/night.json`, утренняя строка — в `memory-brief` (SessionStart, MOTD).

## Изменено
- P5.3: тяжёлые задания MCPshka (`go test/build/vet`, low-priority) больше не делят CPU с сервером. `Delegate=yes` у mcpshka.service: сервер в `server/` (вес 1000), тяжёлое в `heavy/` (CPU/IO вес 10, не больше 3 ядер), запуск сразу в группе через CLONE_INTO_CGROUP. Drop-in ставит `home-priority` вместе с остальными приоритетами, с откатом. Без делегирования всё как раньше.

## Исправлено
- MCP-193: smbd падал по таймауту на холодной загрузке (Armbian задаёт DefaultTimeoutStartSec=10s). Drop-in на 90 с, Restart=on-failure.
- MCP-199: журнал H96 до суток жил в RAM. armbian-ramlog (cron.daily) делал relinquish-var, и 15.11 при отключении света пропало 14 ч. host-hardening отключает это в обоих скриптах Armbian. Сторож теперь видит журнал в /run: прежняя проверка не срабатывала никогда.
- MCP-197: запечатанный тест падал с «read-only file system», когда модулей Go нет в доверенном кэше (у go2rtc не хватало 50 из 54). Перед подготовкой брокер прогревает кэш коротким юнитом: только go.mod/go.sum, proxy.golang.org с проверкой sum.golang.org, без VCS и кода проекта.
