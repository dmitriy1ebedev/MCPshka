# MCPshka 0.1.195

Управление Home Assistant, мастер инструментов, рефакторинг.

**Home Assistant — слой конфигурации (через штатные API HA, без записи в .storage и без shell):**
- `ha_inventory` — сущность → устройство → интеграция → комната → куда экспортирована (HomeKit-мосты, Yaha Cloud/Алиса), признак Zigbee2MQTT, категория (config/diagnostic). Реестры — по WebSocket API, списки экспорта — через options flow интеграций (поток всегда прерывается, ничего не сохраняется).
- `ha_exposure_sync` — plan → apply → restore: добавляет в существующие HomeKit и Yaha только недостающие управляемые устройства и нужные датчики Zigbee2MQTT (служебные, прошивки, диагностика исключены), остальное не трогает; повторный запуск ничего не добавляет; apply только по digest проверенного плана, с резервной копией, сохранением через те же options flow, проверкой и полным откатом при любом сбое. Предупреждает о комнатах, где Zigbee-выключатель может обесточивать свет.
- `ha_entity_update` — имя и комната без смены entity_id, с прежними значениями для отката и проверкой реестра.
- `ha_config_read` — YAML HA (configuration/automations/scripts/scenes/customize/groups) через брокер, пароли и токены замаскированы; secrets.yaml и .storage недоступны.
- Изменения — только при активной Face ID-сессии.

**Инструменты и подтверждения:**
- `tool_forge` — ревизия каталога (дубли, мутации без контрактов, без readiness, неиспользуемые), составные инструменты x_* из существующих после Face ID — доступны сразу, каждый шаг проходит свои проверки; заявки на новый код.
- `tool_resolve` — CAPABILITY_MISSING, если инструмента нет, CAPABILITY_PARTIAL, если цель меняет что-то, а подходят только читающие инструменты.
- `admin_coverage` — нужно ли ничего, активная Face ID-сессия, отдельный грант или операция невозможна, и точное следующее действие.
- Предпроверки до запроса подтверждения: `docker_terminal_open` для контейнера вне allowlist отказывает сразу (и `mutation_approval_request` не создаётся).

**Логи, браузер, ретеншн (Codex):**
- `docker_logs` — страницы с курсором, фильтр по компоненту и уровню на сервере, ограничение длины записи, `truncated` вместо отказа; ошибка инструмента отдельно от содержимого журнала.
- `browser_run` — локальные http:// только по явному allowlist (HA 192.168.77.10:8123), публичные — только HTTPS; диагностика стадии сбоя (запуск Chromium / TLS / навигация / авторизация), раздельные таймауты процесса и загрузки; сохранённая сессия HA под Face ID.
- BUG-20261025-112 до конца: бинарники-кандидаты старых версий сверяются с хешами завершённых выпусков и удаляются; прод и откат защищены.

**Рефакторинг (Codex):** readiness, hosttriage, knowledgeops, toolcontract вынесены из mcpserver; компиляция тестов mcpserver ≈505 → ≈153 с; server.go 1440 → 707 строк.
