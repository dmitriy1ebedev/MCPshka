# MCPshka 0.19.4

Выпуск 26–27.11: Python-раннер и наблюдатель DIAG заменены на Go, гейты вливания проверяют архитектуру сразу, плашка версии на публичных площадках, исправлены сбои agent_task и отмены заданий раннера. Черновики части правок написал GigaChat, проверка и доводка — Claude.

## CI и площадки
- **MCP-291:** публикация кусков distributed CI идёт отдельным заданием тяжёлой очереди со своим бюджетом (360 CPU-с вместо 120). Все куски берут один проверенный экспорт ядра: аудит секретов выполняется один раз.
- **extra_forge.py → Go:** команды CI для GitHub, SourceCraft и GitFlic живут в internal/gitprovider, Python-файлы удалены.
- **Быстрый отказ archlint:** sealed-гейт останавливается сразу после ошибки archlint (секунды вместо полного прогона), integration_ship называет причину.
- **archlint на дереве слияния:** integration_ship и очередь выпуска до CI проверяют потолки на общем дереве всех допущенных веток.
- **Плашка версии:** при выгрузке открытого ядра в README.md и README.ru.md ставится бейдж version-<VERSION>. Он одинаков на GitHub, GitVerse, MosHub и SourceCraft.

## Раннеры (S5.GO.6, MCP-290)
- **Облачный раннер на Go** (cmd/mcpshka-runner): статический бинарь для linux amd64/arm64, протокол runnerhub прежний. agent.py удалён. postStart GigaIDE скачивает бинарь.
- Ассеты раннера вшиваются при сборке (packaging/native/build-runner-assets.sh). Сборка рецептом 0.19.3 их не вшивает, и до следующего выпуска скачивание отвечает 404.
- **job_cancel для rj-…** (MCP-292): отменяет задание раннера в очереди или в работе (раннер получает «стоп» с ближайшим пульсом), а после перехода на H96 — само задание H96.

## DIAG (S5.GO.4)
- Пассивный наблюдатель трафика перенесён в брокер на Go (rootbroker/diagtraffic): формат отчёта, проверка MAC и лимит PCAP прежние. Python-наблюдатель удалён, потолок rootbroker 9553 → 9475.

## Агенты
- **agent_task параллельно:** когда брокер отвечал OWNER_BUSY (занят мьютекс мутаций), оставались worktree-сирота и .prompt, а повтор ключа уходил в FENCED_UNKNOWN. Теперь подготовка откатывается, и тот же ключ можно повторить. git worktree add больше не обрывается дедлайном чата.

## Память и метрики
- **S5.TIDY.2:** файл архива чекпоинта (…checkpoint-archive…) не попадает в индекс; записи, попавшие из него раньше, закрываются.
- **K2.2:** memory_recall audit=true показывает возможные противоречия: факты и решения с почти одинаковым заголовком и разным текстом. Это только список, план optimize они не меняют.
- **owner_nudges (MCP-286):** «продолжай» считается по чатам, где упоминается проект. Если таких чатов нет, считаются все чаты, с пометкой в источнике.

## Безопасность
- **S5.TIDY.4:** без admin_session_id гейт Face ID отказывает. Раньше пустой id читал «текущее окно» и пропускал вызов, пока окно было открыто. Гейт вынесен в internal/adminsession.
