# MCPshka 0.19.1

Выпуск 25.11: баги, найденные в 0.19.0, пункты roadmap и открытое ядро. Код MCPshka становится публичным под Apache-2.0, без секретов, коннекторов и домашних адресов владельца.

## Открытое ядро
- **opencore_preview / opencore_publish:** выгрузка канонического коммита main через `git archive`. Политика лежит в самом дереве (`.mcpshka/opencore.json`: исключения, фикстуры тестов). Адреса владельца (IP интерфейсов, tailnet, MagicDNS, MAC, домашние хосты) берутся с живого хоста, а не из списка руками, и заменяются заглушками того же вида: 192.168.77.x, 100.77.x.x, example.ts.net. Найденный секрет вне фикстур или оставшийся адрес владельца блокирует выгрузку. Дерево с дайджестом пушится в публичный репозиторий без force, повтор того же дерева — UNCHANGED.
- **CI отдельно от публичного кода:** снимки для GitHub CI, зеркало main, шарды и облачные задачи идут в приватный `dmitriy1ebedev/mcpshka-ci`. Пуш снимка в публичный репозиторий отказывается (repository_not_private). Метки квитанций прежние.
- **Лицензия Apache-2.0** (каноничный текст, NOTICE): явная патентная лицензия, товарный знак не передаётся (§6).

## Открытое ядро на четырёх площадках

- `opencore_publish` публикует один экспорт в публичные репо на GitHub (`dmitriy1ebedev/MCPshka`), GitVerse (`dmitriy_1ebedev/MCPshka`), MosHub (`lda6994/mcpshka`) и SourceCraft (`lda6994/mcpshka`). Везде есть LICENSE (Apache-2.0) и NOTICE. Цели заданы в `.mcpshka/opencore.json`; сбой одной площадки не останавливает остальные.
- Оверлей `packaging/opencore/public` попадает только в экспорт. Он даёт каждой публичной площадке свой CI: на каждый push в main запускаются `go vet` и полный `go test` от непривилегированного пользователя.
- Приватные CI-репо везде называются `mcpshka-ci` (MosHub: проект 91385). Прод 0.19.0 слал снапшоты в старые имена, которые теперь стали публичными, поэтому 0.19.1 выпускается с доказательством `module`, без прогона forge_ci.

## Исправлено
- **roadmap_close снова закрывает пункты потоков S1–S5/C1–C2** (MCP-278). Разбор пунктов не видел заголовки `###` внутри потоков, и закрытие PASS-пунктов (S5.13, S5.24–S5.30, K2.x) отказывало. Пересечение позиционного ID с явным получает буквенный суффикс (S5.6a).
- **systemctl через брокер — снова миллисекунды** (MCP-256). Каждый запрос шёл 3,08 с и заканчивался response_write_failed: от root unitbus ходил в приватный сокет systemd. Туда сыплются все сигналы, и под потоком transient-юнитов ответ GetAll не укладывался в 3 с. Теперь основной путь — системная шина (она отдаёт только подписанные сигналы), приватный сокет остался запасным.
- **Zigbee2MQTT поднимается сам после сбоя рестартов Docker.** 25.11 в 04:46 у контейнера умер shim, собственные рестарты Docker не прошли и оставили exit 0 с State.Error. selfheal принял это за docker stop, и дом 1,5 ч был без Zigbee. Теперь exited-контейнер с политикой рестарта и State.Error считается упавшим (P15).
- **Ночной бэкап состояния** снова проходит, а с ним lane-postcheck. Python-помощник ограничивал базу 64 МиБ, хотя Go-хранилище уже держит 65536 страниц, а живая state.db весит 67,8 МБ. Лимит общий: 256 МиБ. Логи заданий (1,9 ГБ) кладутся в бэкап от новых к старым в пределах 32 МиБ, остальное считается в logs_skipped.
- **FAIL из середины лога теста** больше не теряется. Строки --- FAIL / FAIL pkg / panic из вырезанной середины выводятся после маркера пропуска (768 Б).
- **brain_ask** получает валидный JSON: шумовые ключи убираются, длинные строки и списки ужимаются в пределах 12 КБ, вместо обрезки JSON на 6 КБ посередине.
- **FreeLLM «auto»:** endpoint с BrainModel больше не отбрасывается фильтром моделей.

## Только Go (S5.GO, решение владельца 25.11)
- **Почему:** выпуск меняет бинарники, но не Python-помощники в /usr/local/libexec и не юниты. Исправления Python до H96 не доходили: ночной бэкап падал с 21.11, а на хосте стояла версия помощника от 26.10.
- **Храповик TestNoNewPython:** новый .py роняет тест; список оставшихся (`internal/archlint/python_allowlist.txt`) может только сокращаться.
- **Бэкап состояния — Go внутри брокера** (`internal/statebackup`): квитанции прежние; онлайн-копия базы от имени её владельца; логи в бюджете 32 МиБ; age → rclone в закреплённую папку Диска → скачивание, обе контрольные суммы, расшифровка и восстановление в scratch. Расписание в брокере (после 04:30), старый таймер отключается сам.
- **Удалено наследие:** state-backup.py с юнитом и таймером, ручной updater-helpers, разовые помощники обновления 0.1.109/0.1.129, исторические лабораторные скрипты. Осталось 41 файл, план волн — поток S5.GO в ROADMAP.

- Будильник раннеров GitHub/GitVerse/MosHub — один POST через gitprovider, без Python.
- Публикация открытого ядра на Go (`opencore.Publish`).
- `forge_ci` для GitVerse на Go: снапшот, зеркало main, перезапуск и статус с разбором падения.
- Удалены Python-скрипты без вызывающих (cloud fanin/hooks/agent_tasks, push_snapshot, github_ssh_preflight, battle-smoke).
- brain_ask сокращает старые результаты под окно модели. GigaChat падал на 11-м шаге с «input over limit».

## Code Mode
- **mcp.mutate в code_run (S5.CM.6):** мутирующий инструмент с контрактом мутации вызывается только со своим idempotency_key, иначе POLICY_DENIED, и вызов не отправляется. Face ID, lease и квитанция — те же, что у прямого вызова. Вызовы идут по одному, не больше 10 за прогон. Ответ, потерянный на завершении скрипта, приходит как UNKNOWN с ключом для повтора. Approval-only инструменты и диспетчеры по-прежнему вызываются только напрямую.
