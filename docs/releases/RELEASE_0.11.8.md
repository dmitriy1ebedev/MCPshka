# MCPshka 0.11.8 — «Выпускает что угодно»

## Универсальный выпуск проектов (MCP-171)

Задача владельца 11–12.11.2026: «это должно применяться не только к DIAG или Lane, а вообще ко всему, что я захочу». До 0.11.8 MCPshka умела довести до прода только себя и DIAG; Lane ставился из root-консоли.

- Новые инструменты `project_release` и `project_release_status` — один путь для любого проекта в `/root/repos`.
- Проект сам описывает выпуск в `.mcpshka/release.json` (схема `mcpshka.release/v1`): шаги с фиксированным argv без shell, `root`, таймаут, `expect` / `fail` по выводу, `retry_seconds` (ожидание gate или обновления), `capture` (значение из вывода для следующих шагов), `version_file`, `env`, `rollback` и `rollback_from`.
- Рецепт берётся из выпускаемого коммита. Коммит обязан быть на main, рабочая копия — чистой и ровно на нём.
- Рецепт владелец подтверждает один раз по Face ID: его SHA-256 закрепляется записью root. Новый или изменённый рецепт → `RECIPE_NOT_APPROVED` и готовый план подтверждения; чат не может дописать себе root-команду правкой файла.
- Отказ шага начиная с `rollback_from` запускает `rollback`; итог — `INSTALLED`, `FAILED`, `ROLLED_BACK` или `ROLLBACK_FAILED` с хвостом вывода каждого шага.
- Добавить проект = положить файл рецепта; код MCPshka не меняется. Логика — в `internal/projectrelease`.

Что не сделано: рецепты самих проектов (Lane, DIAG, «чужой» проект) и их живая приёмка — карточка MCP-171 остаётся открытой до первого выпуска Lane этим путём. `diag_release_apply` пока работает как раньше.

## Аудит инструментов (владелец 12.11: «дубли исключи», «не удаляем, а в копилку»)

Отчёт `tool_forge action=audit`: 286 зарегистрировано, 249 в каталоге, 138 без единого вызова с 08.11. В «копилку» (скрыты из `tools/list`, вызываются по имени и через `tool_invoke`, записаны в память «Копилка инструментов») ушли три дубля:

| Инструмент | Чем покрыт |
|---|---|
| `idempotency_status` | `mutation_probe` |
| `knowledge_read` | `memory_recall` (`id=`) |
| `project_detect` | `project_context` |

Не тронуты: `gateway_*` (ядро малого шлюза и маршруты восстановления), `root_task_*` (единственный путь автоматизаций Home Assistant), `approval_gate_status` (используется сценарием), `knowledge_local_read` (история правок статей).

## Мелочи

- Успешный автовыпуск больше не оставляет напоминание в MOTD («напомнить: Автовыпуск …»); напоминание остаётся только при остановке.
