# MCPshka 0.18.0

Ночной выпуск 23–24.11: память, порядок в коде, раннеры и CI. Включает несостоявшийся 0.17.6: GitHub CI в тот вечер отклонял задания.

## Память (S4.K2)
- **Аудит памяти:** `memory_recall audit=true`. Только читает. Находит:
  - устаревшие секции чекпоинта и журналов (раздел старше последнего или старше 7 дней);
  - дубли текста;
  - старые факты «X a.b.c в проде»;
  - записи без источника.

  Отдаёт план и его `plan_sha`, а также контрольный набор из 30 вопросов о текущем состоянии (fresh@3).
- **Оптимизация:** `memory_write optimize=<plan_sha>` применяет ровно этот план под окном Face ID. Записи уходят в архив или помечаются superseded, ничего не удаляется. Журнал ведётся в `mem_ops`. `optimize_undo=<op>` возвращает записи. Сводки дня и недели пересобирает ночная консолидация. Root на H96 может сделать то же через `mcpshka memory-audit|memory-optimize|memory-undo`.
- **Проверено на копии живой базы 23.11:**
  - план — 135 операций: 130 старых секций чекпоинта и 5 повторов напоминаний;
  - fresh@3 вырос с 0.90 до 1.00;
  - экзамен памяти дал R@1 0.86 и R@3 0.98.
- **Экзамен памяти снова проходит порог.** На живой базе прод давал R@1 0.80 (порог гейта 0.85): свежие выжимки чатов обгоняли правила, на которые ссылаются. Целые файлы Claude-памяти (feedback, project, user) теперь считаются каноном (вес 1.25). Вес архива снижен до 0.4.
- **Импорт сессий:** `mcpshka memory-sync` дописывает в inbox памяти новые ходы сессий Claude Code и Codex. Берутся только слова владельца и итоговый ответ, секреты маскируются. Смещение по каждому файлу хранится, поэтому повтор ничего не дублирует, а прерванный импорт продолжается. `memory_recall inbox=true` отдаёт до 10 кусков за вызов.

## Раннеры и CI
- **Реестр раннеров:** `runners.json` и его блокировка сохраняются с владельцем каталога. Root-таймер MOTD больше не отбирает файл у службы (бывший 0.17.6).
- **Раннер не умирает от сбоя сервера.** Нечитаемый реестр теперь отдаёт 503, а не «key refused». Агент пережидает 401 и 403 до 30 минут. В 20:37 23.11 из-за этого GigaIDE-раннер вышел насовсем.
- **Диагноз GitHub (S5.DIAGCI):** если все задания упали с 0 шагов и без раннера, это `CI_ACCOUNT_BLOCKED`, то есть минуты Actions или billing. `integration_ship` советует восстановить минуты или выпускать с `evidence=module`, а не «исправь и сделай новый коммит».
- **Автостоп GitVerse.** Три отмены подряд у одного коммита дают `CI_STUCK`: повторные публикации и перезапуски прекращаются, заводится одна карточка P2. Решает GitHub или `evidence=module`. 17–23.11 GitVerse отменил 34 прогона подряд.
- **Асинхронный code_run (S5.CM.5):** `async=true` запускает скрипт фоновым заданием, которое переживает закрытый чат: ожидание CI и чтение логов. Результат — через `job_wait` и `job_output`.

## H96
- **Автоснятие протухших лизов (S5.LEASE).** Root self-heal снимает лиз сам, только если все условия выполнены:
  - heartbeat старше 2 ч;
  - держатель доказуемо мёртв (нет процесса, задания или процесса в дереве);
  - дерево чистое и HEAD уже в main.

  Остальные лизы остаются с причиной. Автовыпуск после DONE применяет то же правило перед уборкой слитых worktree: 0.17.4 оставил два таких дерева под мёртвыми лизами.
- **P5.3:** весь `mcpshka-heavy.slice` ограничен CPUQuota 300%, CPUWeight 20 и IOWeight 10. Одно ядро всегда остаётся дому.
- **FreeLLM:** в сводке «ждут проверки» считает только зелёные ветки. Карточки без патча показываются отдельно.
- Страница «Вход на сайт» убрана из меню.
