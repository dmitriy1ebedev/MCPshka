# MCPshka 0.13.0 — разбор mcpserver и сеть важнее сборок

## Зачем

`internal/mcpserver` разросся до 17,5 тыс. строк: любая правка задевала всё сразу, конфликты веток шли постоянно. Codex по шагам вынес семейства инструментов в отдельные пакеты, Claude Code параллельно вёл исправления из живой работы 14.11.

## Рефакторинг (Codex)

- 26 коммитов, каждый — один перенос с зелёными тестами; `mcpserver` 9 998 строк (было 17 478), rootbroker и executor — по две подсистемы наружу.
- Поведение не менялось: снимок `tools/list` (294 инструмента) совпадает байт в байт; имена типов схем сохранены.
- Защита не ослаблена: `protectedcore.SourcePrefixes` и archlint-гард памяти расширены на вынесенные security-пакеты.

## Сеть важнее сборок

14.11 днём сборка выпуска DIAG шла параллельно с тестами агента — load 14 на 4 ядрах, DNS и туннели Lane тормозили, у Apple TV и айфонов «ничего не грузит». Сборка DIAG была единственной тяжёлой задачей без `CPUWeight=20` и вне `heavyqueue`. Теперь она как все: уступает CPU и ждёт очередь (до 15 мин). На хосте сетевые службы получили `CPUWeight=1000` (drop-in `50-gateway-priority.conf`, тумблер — ROADMAP Lane HP).
