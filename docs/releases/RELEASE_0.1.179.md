# MCPshka 0.1.179 — автоочистка, очередь тяжёлых задач, ход миссии, честный health

- Автоочистка (Codex): после release_apply и раз в час хранятся только текущий выпуск, откат и неустановленные запечатанные сборки со всеми их доказательствами; удаляются устаревшие образы bin, upgrade-каталоги, workspaces/release-artifacts FENCED permit вне защищённых, остатки .part/.done. Не больше 8 объектов за проход, неизвестное не трогается (регресс BUG-20261023-82). Описание — docs/HOST_CLEANUP.md.
- Очередь тяжёлых задач (Codex): go build/test/vet, подготовка executor и agent_task идут по одной и при load1 ≤ 1,5×CPU; ответ QUEUED с причиной и позицией; подготовка получает 720 с после допуска (BUG-20261023-81).
- host_storage_inventory: топ каталогов, рост по снимкам, прогноз заполнения; health предупреждает при остатке ниже max(3 ГиБ, 10%) или прогнозе на 72 ч.
- P8 (Codex): read-only `mission_status` и сводка в `health_snapshot` — прогресс, застывшее доказательство, остановленный воркер; застывание даёт `degraded` с безопасным следующим шагом, без передачи lease.
- BUG-20261023-81: подготовка сборки на нагруженном хосте упиралась в бюджет воркера 160 с и возвращала голый «executor HOLD». Теперь ошибка называет подкоманду git и исчерпанный бюджет.
- BUG-20261023-83: `agent_task` помечал успешно завершённую задачу как `quota`, если в выводе встречались слова о лимите (описания инструментов). При чистом выходе лимит определяется только по последним строкам.
- BUG-20261023-84: `search_index` в health становился stale через 5 минут после переиндексации, хотя индекс совпадал с ревизией знаний.
- BUG-20261023-85: executor в health был UNKNOWN без причины — скан permit не укладывался в 1 с под нагрузкой. Свой бюджет зонда и поле `reason`.
- CI-площадки: SourceCraft (race на пакетах с конкурентностью, сборка amd64) и GitFlic (контракты площадок, vet, короткий fuzz) дополняют шлюз GitVerse.
