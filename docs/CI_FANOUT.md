# CI fan-out: площадки делят работу, а не повторяют её

Решение владельца 2026-11-03: «не гонять одно и то же на площадках, а дробить, балансировать нагрузку».
План — `packaging/ci/plan.json`, планировщик — `packaging/ci/shard.py` (LPT по измеренному весу пакета и скорости площадки; детерминирован, каждая площадка сама вычисляет одинаковый план и берёт только свою долю).

| Площадка | Роль | Что запускает |
|---|---|---|
| GitVerse | обязательный шлюз интеграции | `snapshot-contracts` на неизменяемом снапшоте: полный `go test`, `go vet`, build matrix — один раз на коммит (запуск `ci.yml` на push в main убран: он повторял снапшот) |
| MosHub | race, доля A | `go test -race` своей доли пакетов (офлайн-образ) |
| GitHub | race, доля B; fuzz; ARM64-релиз | `cloud.yml` dispatch: `suite=race` (своя доля), `fuzz`, `release-arm64` |
| Ноутбук | E2E, sandbox | `remoterunner` (при недоступности — H96 в очереди) |
| H96 | прод | только точечные тесты и финальная запечатанная сборка |

- **Недоступная площадка:** её доля уходит оставшимся — `SHARD_SITES` (MosHub: CI-переменная; GitHub: input `shard_sites`), например `github` — GitHub берёт весь race.
- **GitHub как шлюз** (GitVerse недоступен): PR в main запускает полную матрицу `evidence=ci`; race в этом режиме покрывает все пакеты.
- **Веса** — секунды `go test` на пакет из последнего полного прогона GitVerse; неизвестный пакет получает медиану. Пересчёт: распарсить `ok <pkg> <N>s` из лога snapshot-contracts и обновить `weights`.
- **Готовность релиза:** шлюз GitVerse PASS + обе race-доли PASS для одного SHA (+ fuzz/ARM64 GitHub).
