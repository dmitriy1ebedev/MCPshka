# Агенты MCPshka

Разработку по умолчанию ведёт ИИ текущего чата штатными инструментами. Codex, Claude и другие исполнители-ИИ запускаются только по прямому разрешению владельца; разрешение на разработку или релиз само по себе не разрешает дополнительных ИИ.

- `agent_task` требует явно указанного разрешённого исполнителя. `roadmap_run` дополнительно требует `allowed_agents`: например, `["codex"]`. Не добавляй Claude из-за квоты Codex без отдельного разрешения.
- Перед запуском: `project_context`, checkpoint, leases/jobs/deploy, доступность разрешённого исполнителя и Face ID. Неизвестная квота остаётся неизвестной. Запрет исполнителя не является неисправностью проекта.
- Задача должна содержать путь, цель, критерии приёмки, разрешённые действия, бюджет, текущий WIP и следующий безопасный шаг. Состояние запуска отслеживай через `agent_task_status` или `roadmap_run_status`, а не по тишине чата.
- Автопродолжение квоты допустимо только внутри ранее разрешённого исполнителя и исходного бюджета: известный будущий reset_at + 1 мин, successor с resume_of и resumed_by в исходном статусе. Общий бюджет 8 ч, до 3 продолжений. Неизвестный/устаревший reset, исчерпанный бюджет или interrupted требуют точного next_action. После ребута ожидавший раннер помечается interrupted; автоматический старт после ребута пока не реализован. Не расширяй список исполнителей и не продлевай согласие.
- Переподключение: сначала durable status и исходный receipt; UNKNOWN требует reconcile. Новый чат не наследует власть из имени owner. Безопасная передача lease требует штатного handoff с fencing; чужой токен не извлекай из журналов.
- Брошенный lease снимается только по проверенному доказательству завершения владельца и существующей процедуре с Face ID. Возраст файла и отсутствие jobs сами по себе не доказывают право перехвата.
- Параллельные исполнители используют независимые управляемые worktrees, один писатель на scope. Запрет владельца на дополнительных агентов исключает их запуск и для ревью.
- Обычные проекты: ff-merge под lease целевого worktree, затем sealed project_test чистого HEAD. integration_ship предназначен для защищённого MCPshka.
- Перед завершением сверяй фактический результат, исходники и receipts; сохраняй checkpoint; освобождай только собственные ресурсы. Успех исполнителя не заменяет интеграцию, релиз и production acceptance.

Обычная административная сессия работает в native_only. Только по прямой просьбе владельца передай admin_session_begin.agent_consent={path, agents}: точный проект и имена codex/claude/codex_cloud/claude_cloud будут показаны перед Face ID. Сервер сверяет этот scope при каждом новом запуске; allowed_agents не является разрешением. Для смены scope закрой текущую сессию и получи новое подтверждение. Сверка и отмена существующей задачи остаются доступны; native_only не разрешает перехват её lease.
