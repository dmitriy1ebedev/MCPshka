# Восстановление

- Обрыв, timeout, потеря ответа, перезапуск — UNKNOWN до сверки исходных receipt/job/workflow/deployment IDs. gateway_reconcile использует исходные tool/key/input через mutation_probe; он не повторяет эффект и не снимает fencing.
- Источники ошибок различаются: client report (UNTRUSTED), ответ MCPshka policy/admission, наблюдаемый receipt исполнителя. Отсутствие receipt не доказывает, что запрос не дошёл: отказ возможен до создания receipt. interaction_recovery_diagnose даёт гипотезу и безопасную следующую проверку.
- Старый каталог клиента: capabilities_bootstrap/tool_resolve → tool_invoke с текущими внутренними аргументами. Обновление connector делает клиент; стабильный Gateway не зависит от обновления внутренних схем в кеше. Не применять fallback для обхода OpenAI safety, Face ID, policy или owner fencing.
- Сначала выбери минимальные права. Для разрешённого свободного scope — прямой SHA CAS; для собственного held scope — текущий token. Отказ acquire не доказывает запрет CAS, но сам CAS также обязан пройти свои независимые проверки.
- Один job остаётся одним job после обрыва. Сверь job_status/job_output и фактический effect. Не создавай новый retry key при PENDING/UNKNOWN. Known no-effect failure допускает исправленную операцию только после terminal evidence.
- Умерший worker без результата не означает отсутствия эффекта. Новый approved_task запускается по Face ID сервером один раз; consumed-unrecorded сохраняет UNKNOWN. Expiry аннулирует challenge без автоматического renewal.
- Восстановление lease: собственный idle release либо token-bound project_lease_resume. Чужой owner требует доказанной утраты authority и штатного audited recovery; возраст, 0 jobs, совпадение имени или желание сменить задачу не являются proof.
- Независимый разрешённый маршрут проверяй отдельно: собственные admission, CI, source identity, approval, rollback и acceptance. Отказ одного маршрута не разрешает shell/RDC/root обход. Зарегистрированный профиль ещё не означает, что установленный backend умеет его исполнить.
- Сохраняй один durable checkpoint: план/scope, Git/ROADMAP hashes, stage и evidence, оригинальные IDs/keys, lease identity без token, что UNKNOWN, следующий безопасный шаг. При отмене/ошибке finally-cleanup только собственных подтверждённо idle ресурсов.
- Host health, executor readiness, provider auth, client catalog и project acceptance проверяй раздельно. Не подменяй долгий или неизвестный исход успехом. Не запускай Codex/Claude или quota fallback без прямого разрешения владельца.

- Разрешённый agent_task держит lease в root-раннере и передаёт его только своей попытке. Исполнитель не захватывает, не передаёт и не освобождает этот lease. Task.lease сохраняет исходные acquire_key/release_key без token; после подтверждённого выхода раннер проверяет idle и освобождает lease до ожидания quota. UNKNOWN попытки, heartbeat или cleanup запрещает автоматического преемника и ручной resume до сверки исходных ресурсов. Потерянный acquire-ответ восстанавливается только после read-only proof завершённого исходного receipt, с тем же caller/ключом/входом; отсутствие receipt не разрешает повтор.
- Task.state=done означает завершение процесса исполнителя, а не приёмку проекта. Полный результат требует проверок, интеграции, разрешённого релиза/установки и production acceptance по критериям mission. Оборванный root-раннер требует доказательства завершения его unit и сверки исходных lease/receipts; возраст и отображаемое имя не разрешают освобождение.
